2
Git is een programma waar je bestanden/projecten kan in opslaan. Voor 1 bestand kan je verschillende versies aanmaken en op branches werken. Als je tevreden bent over de branches kan je deze op de main zetten door een pull request te doen. GitHub is een site waar je deze bestanden kan bekijken en pull requests kan nakijken. Je kan met meerdere mensen aan 1 project werken, door verschillende branches te gebruiken. 
Ik wist zelf niet wat een origin was, maar heb dit wel al zien staan na een git status te doen: "Your branch is up to date with 'origin/main'". Ik dacht dus dat dit de main was van een bestand/project. Ik heb online gelezen dat de origin de naam is die Git geeft aan de online repository waarmee mijn lokale repository verbonden is.

4
  Een docker gebruik je om een container te maken. Bij deze opdracht is dit op basis van Nginx. Hier stonden de bestanden in om de website te kunnen uitvoeren. Een container is een omgeving waar een programma en wat het programma nodig heeft samen verpakt staan. Hierdoor kan het programma op verschillende locaties op dezelfde manier draaien. Het verschil met een virtual machine is dat een VM een eigen besturingssysteem nodig heeft. Een container deelt de kernel van het bestaande besturingssysteem. Een container werkt hierdoor sneller dan een virtual machine. 
  Ik ben heel wat problemen tegengekomen. Ik kon Docker niet rechtstreeks op mijn laptop installeren, dus heb dit via Ubuntu gedaan. Ik moest eerst Docker Engine installeren en controleren of deze juist werkte. Mijn project stond eerst in een gedeelde map tussen Windows en VirtualBox. Hierdoor kon Nginx mijn bestanden niet lezen. Ik heb daarom mijn project gekopieerd naar een map in Ubuntu. Daarnaast hadden mijn bestanden niet de juiste rechten. Ik heb dit meerdere keren proberen aanpassen maar het lukte niet. Bij dit probleem heb ik de hulp van AI gebruikt, omdat ik niet wist wat ik moest ingeven in mijn terminal.

Bij een foute commit kan je git revert HEAD gebruiken. Hierdoor maak je een nieuwe commit aan die de wijzigingen ongedaan maakt, maar kan je nog steeds de vorige versies zien.

  Ik heb met verschillende branches gewerkt. Dit is een aparte omgeving, niet op de main, waar je wijzigingen kan maken. Het is een veilige manier om zaken uit te proberen of wijzigen zonder het project definitief aan te passen. Ik heb er 2 aangemaakt: feature/docker en feature/readme. Hier heb iik de dockerconfiguratie en README aangepast. Een push kan je gebruiken om commits up te loaden naar GitHub. Een pull kan wijzigingen van GitHub ophalen en op de branch samenvoegen waar je aan het werken bent. Een fetch kan kan dit ook, zonder ze automatisch samen te voegen. Bij een pull request vraag je of de wijzigingen van jouw branch op de main (of andere branch) gezet mag worden. Ik heb 2 pull requests gemaakt en op de main gezet.
